CS2: Data Structures, Algorithms and Complexity

Year 1 / ASYear 2 / A-Level All Boards (AQA, Edexcel, OCR, WJEC, CCEA) AQA

Stacks, queues, linked lists, binary search trees, Big-O notation, Dijkstra's algorithm, sorting (Merge, Quick, Bubble).

📋 Key Definitions and Core Concepts

Big-O Notation: Mathematical classification of algorithmic efficiency in terms of time and space scaling with input size n.
Dijkstra's Algorithm: Single-source shortest path algorithm on weighted graphs using a priority queue.
Complexity Classes: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ); binary search is O(log n), merge/quick sort O(n log n), bubble/insertion sort O(n²).
Linear vs Binary Search: Linear search checks each item in turn on any list — O(n); binary search needs a sorted list and halves the search space each comparison — O(log n).
Stacks and Queues: A stack is LIFO (push/pop) — used for call stacks and depth-first search; a queue is FIFO (enqueue/dequeue) — used for print buffers and breadth-first search.
Tree Traversals: Pre-order (root, left, right), in-order (left, root, right — outputs a BST in sorted order), post-order (left, right, root); graphs are traversed by BFS (queue) or DFS (stack/recursion).
Hash Tables: Average O(1) lookup by applying a hash function to the key; collisions resolved by chaining or open addressing; a high load factor triggers resizing to keep performance.

🔍 Key Principles & Specification Requirements

  • Time complexities: Binary search O(log n), Merge sort O(n log n), Bubble/Insertion sort O(n²), Hash table lookup O(1).
  • Data structures: Stack (LIFO: push/pop), Queue (FIFO: enqueue/dequeue), BST (left < node < right).
  • Graph traversals: Depth-First Search (DFS using stack/recursion), Breadth-First Search (BFS using queue).

💡 Worked Example Question

Exam-Style Question

Question:

Trace a binary search for target 18 in array [2, 5, 8, 12, 16, 18, 24, 30].

Model Solution & Mark Scheme:

Array length 8, indices 0..7.
1. mid = (0+7)//2 = 3 (val = 12). 18 > 12 => search right half [4..7].
2. mid = (4+7)//2 = 5 (val = 18). 18 == 18 => Target found at index 5. (2 comparisons total).

Q3: State the time complexity of binary search and explain why the list must be sorted first.

Show Model Answer

Answer: O(log n): each comparison halves the remaining search interval, so k comparisons can locate a target among 2^k items. The list must be sorted because discarding one half is only valid if the target cannot lie in it — with unsorted data the target could be in the discarded half, so the halving logic breaks down.

Q4: Compare the number of comparisons made by merge sort and bubble sort when sorting a list of 1024 items.

Show Model Answer

Answer: Merge sort ≈ n log₂ n = 1024 × 10 = about 10,240 comparisons. Bubble sort ≈ n²/2 = 1024²/2 ≈ 524,000 comparisons in the worst case — roughly 50 times more. Merge sort's O(n log n) growth means the gap widens rapidly as n increases.
